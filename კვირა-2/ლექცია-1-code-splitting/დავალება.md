## აღწერა

მოცემულია **MovieHub** — React აპლიკაცია 5 გვერდით (Home, Movies, Favorites, Stats, About). აპი მუშაობს, მაგრამ **Code Splitting არ აქვს** — ყველა გვერდის და კომპონენტის კოდი ერთ bundle-ში იტვირთება.

შენი ამოცანაა: **აღმოაჩინე პრობლემა, გამოასწორე Code Splitting-ით, და დაადასტურე შედეგი.**

Code Splitting გვეხმარება კოდის ნაწილ-ნაწილ (დინამიურად) ჩატვირთვაში, რაც აუმჯობესებს ვებ-გვერდის მუშაობის სიჩქარეს და ამცირებს საწყისი ფაილების ზომას.

## ნაწილი 2: Route-based Code Splitting

შეცვალეთ `src/App.jsx` — ყველა გვერდის import გადააკეთეთ `React.lazy()`-ზე და დაამატეთ `<Suspense>`.

### ამოცანა:

- [ ] Home, Movies, Favorites, Stats, About — ყველა `lazy(() => import(...))`-ით
- [ ] `<Suspense fallback={<div>Loading...</div>}>` wrapper
- [ ] აპი კვლავ მუშაობს ყველა გვერდზე

### შემოწმება:

```bash
npm run build
```

ჩაწერეთ:
- რამდენი JS ფაილი შეიქმნა ახლა? 8
- Home-ზე ჩასატვირთი JS ზომა: 28kB

## ნაწილი 3: Component-based Code Splitting

Movies გვერდზე `MovieChart` კომპონენტი მხოლოდ "Show Rating Chart" ღილაკზე click-ისას ჩანს — მაგრამ მისი კოდი ყოველთვის იტვირთება.

### ამოცანა:

- [ ] `src/pages/Movies.jsx`-ში `MovieChart` import გადააკეთეთ `lazy()`-ზე
- [ ] `showChart && <MovieChart>` ადგილას დაამატეთ `<Suspense>`
- [ ] Stats გვერდზეც იგივე გააკეთეთ `MovieChart`-ისთვის

### შემოწმება:

Network tab-ში ნახეთ — "Show Rating Chart" ღილაკზე click-ისას **ახალი JS request** ჩნდება?

## ნაწილი 4: Dynamic Import — Utility ფუნქცია

Stats გვერდზე `generateMovieReport()` ფუნქცია "Generate Full Report" ღილაკზე click-ისას გამოიძახება — მაგრამ `movieData.js` მთლიანად იტვირთება.

### ამოცანა:

- [კი] `src/pages/Stats.jsx`-ში `generateMovieReport`-ის import წაშალეთ ზემოდან
- [კი] ღილაკის click handler-ში გამოიყენეთ dynamic import:
  ```jsx
  const handleReport = async () => {
    const { generateMovieReport } = await import("../utils/movieData");
    setReport(generateMovieReport());
  };
  ```
- [კი] აპი კვლავ მუშაობს — ღილაკზე click-ისას report ჩნდება

### შემოწმება:

Network tab-ში ნახეთ — ღილაკზე click-ისას **ახალი request** ჩნდება movieData chunk-ისთვის?
- [movieData.js] კი

## ნაწილი 5: შედეგების შედარება

### 5.1 Build შედარება

```bash
npm run build
```

| | ადრე (ნაწილი 1) | ახლა |
|---|---|---|
| JS ფაილების რაოდენობა | ნაკლები (მაგ. 3-4 ფაილი) | მეტი (8 ფაილი, გამოჩნდა ცალკეული chunk-ები) |
| მთავარი bundle (gzip) | დიდი (~120-150 kB) | პატარა (~40-60 kB) |
| Home-ზე ჩასატვირთი JS | მთლიანი პროექტის ზომა |მხოლოდ Home და App კომპონენტების ზომა (~20-30 kB)|

### 5.2 Coverage Tab შედარება

ისევ Coverage Tab — Home გვერდზე:
- გამოუყენებელი JS: 20-30% (ადრე: 60-70%)

### 5.3 Network Tab დაკვირვება

1. Home გვერდზე — რა JS ფაილები ჩაიტვირთა?
ძირითადი ბუნდლი (main.js / App.js), vendor-ის ფაილები და თავად Home.jsx-ის შესაბამისი ჩანკი/ფაილი.

2. Movies-ზე გადასვლისას — რა ახალი request გაჩნდა?
Movies.jsx გვერდის კომპონენტის შესაბამისი ცალკეული JS ჩანკი (chunk request).

3. "Show Rating Chart" click-ისას — რა ახალი request?
რეიტინგების დიაგრამის/გრაფიკის კომპონენტის დინამიურად ჩატვირთვის ახალი JS request.

4. Stats-ზე "Generate Full Report" click-ისას — რა ახალი request?
movieData.js ფაილისა და ანგარიშის გენერაციის ლოგიკის შემცველი ახალი JS chunk request, რომელიც დინამიურად იტვირთება ღილაკზე დაჭერისას.
